## How to investigate
Read the highest-value sources first: README files, root manifests, workspace config, lockfiles; build, test, lint, formatter and typecheck config; CI workflows and pre-commit config; existing instruction files (AGENTS.md, CLAUDE.md, .cursor/rules, .github/copilot-instructions.md).
If the architecture is still unclear, inspect a small number of representative code files to find the real entrypoints and package boundaries. Prefer executable sources of truth (scripts, config) over prose; if docs conflict with config, trust the config.

## What to extract
- exact developer commands, especially non-obvious ones; how to run a single test or package; required command order (lint -> typecheck -> test)
- monorepo boundaries, the real entrypoints, ownership of major directories
- framework or toolchain quirks: generated code, migrations, special env loading, dev servers
- testing quirks: fixtures, required services, flaky or expensive suites
- important constraints from existing instruction files worth preserving

## Writing rules
Include only high-signal, repo-specific guidance. No generic advice ("write clean code"), no long file trees, no restating what the README already says, no speculation. If an `AGENTS.md` already exists, improve it in place and keep what is still accurate. Keep it short enough to read in a minute.
